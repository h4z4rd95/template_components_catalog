01

What this repository is

A visual catalogue of production-ready web elements: hero sections, navigation systems, loaders, scroll effects, footers, dashboards and commerce pages, each one a real page rather than a screenshot. One manifest — catalog/catalog.json — describes every variation, and everything else in the project is generated from it: the hub, the browse and component pages, the menus, the metadata HUD, the downloadable archive.

Everything is bilingual (English and Persian, LTR and RTL) and ships in both a day and a night theme. That is not a translation layer bolted on at the end: each variation states its own copy in both languages and its own palette for both themes.

02

Run it

  • npm run preview is the honest one: it serves exactly the files a browser gets, so what you see is what a visitor sees.
  • Framework variations need npm run build once: their exported pages live in docs/framework/**, which is generated and never committed.
  • Serve it over HTTP rather than opening docs/index.html from disk: the hub fetches its manifest, and file:// blocks that. There is a fallback, but a server is the real path.
npm install          # workspaces: the catalogue, two framework apps, the shared package
npm run dev          # sync the manifest, then run the Next.js app with hot reload
npm run preview      # serve docs/ as it is — the buildless showroom, no bundler
npm run build        # sync → static-export both framework apps → splice into docs/ → rebuild the ZIP
03

Take one element into your own project

Every variation is self-contained. Pick it from the catalogue, open its component page, and follow the route it names — the element is one folder plus its dependencies, with no catalogue code inside it beyond the shared helpers it imports.

Next.js — copy src/heroes/<slug>/ (or src/nav/<slug>/) into your app, add the dependencies the component page lists, and render it from a client component with ssr: false.

Nuxt — the Vue variations are ordinary SFCs; copy the folder into app/components/ and import the TresJS or GSAP packages they name.

No framework at all — the vanilla variations are single HTML files with two same-origin vendored assets and no CDN. Open one, keep the <style> and <script> blocks, delete what you do not need.

// src/app/hero/<slug>/page.tsx — the three lines that actually matter
export function generateStaticParams() {
  return catalog.variations.filter((v) => v.status !== "planned").map((v) => ({ slug: v.slug }));
}
export const dynamicParams = false;
04

Make an element bilingual and dual-theme

The catalogue shell owns language, direction and theme. Because variations render inside an iframe, the shell hands that state over twice: through the localStorage keys it persists (catalog:locale, catalog:theme) plus ?lang= / ?theme=, which is what makes a reload of the frame land correctly; and through postMessage({ type: "catalog:skin" }) on every change, which is what makes it instant.

Import the hook, spread the attributes, and read copy through lex():

  • Nothing hard-codes a language: the Persian in your component is a second string next to the English one, in the same file.
  • Direction is CSS, not JavaScript: use logical properties (margin-inline-start, inset-inline-end) and the layout mirrors itself for RTL.
  • Test in all four combinations — English/Persian × day/night. A layout that only fits in English is the most common bug in this catalogue, and it is invisible until you measure in Persian.
import { lex, skinAttributes, useCatalogSkin, useSkinDocument } from "@/lib/skin";

const skin = useCatalogSkin();                     // { locale, theme, dir } — follows the shell live
useSkinDocument(skin, { dark: "#07070c", light: "#f6f5f1" });   // <html> + the canvas colour

<div {...skinAttributes(skin)}>                    // scoped CSS: [data-theme], [dir], [data-locale]
  <h1>{lex({ en: "Command", fa: "فرمان" }, skin.locale)}</h1>
</div>
05

Add your own variation

One manifest entry is the whole registration. The id has to match {Discipline}_V##_StyleCodename, and a shipped variation needs its Persian fields — the sync gate refuses to generate a catalogue whose Persian side is missing.

  • npm run catalog:sync — validates the entry, vendors what the variation needs, and regenerates the pages, menus and metadata.
  • npm run build — exports the framework apps and rebuilds the downloadable archive.
  • The new variation now has a card on the hub, a component page, entries in every menu, and a place in the browse tree — none of which you wrote.

06

Check it before you ship it

Five gates, each one written after a real bug that pixels caught and a DOM assertion had passed. They need a preview server (npm run preview) except for npm test.

  • npm test — manifest sync, CSS-module integrity, typecheck, and a jsdom smoke test of the whole shell.
  • npm run verify:cards — every card on the hub, in four skins: a plan card must never promise a live preview.
  • npm run verify:pages — that every generated page loads its assets, that *every internal link exists on disk*, and that a page does not paint the same background in both themes.
  • npm run verify:header — the masthead on a phone, a tablet and a desktop: nothing clipped, nothing wrapped, the download panel inside the viewport.
  • npm run verify:nav — the navigation variation: direction, theme, canvas colour, a trigger row that never clips, and the phone sheet.
07

The gaming-news blueprint

docs/sites/gaming-news/ is a complete newsroom assembled from the catalogue's own parts: the same tokens, the same Persian fonts, the same day/night and RTL behaviour, and three of the variations reused as its banner slots.

The lead story runs the scanner-HUD hero live in an iframe; the reviews desk runs the letterpress hero as its cover spread; the live page runs the raymarched nebula as its banner. If a framework build is missing, each slot says so instead of showing an empty rectangle.

To fork it: copy sites/gaming-news.json, point scripts/site.mjs at your file, and the newsroom is yours — content in JSON, layout in one generator, everything else from the catalogue.

08

Download and licence

The masthead's Download button hands over the whole project as one archive, rebuilt by npm run build from git ls-files so it is exactly what the repository tracks at that revision. The generated motion reel (~26 MB) and the framework build output are excluded; everything else — both apps, the vanilla track, the shared package, the scripts, the docs and these pages — is inside.

The code is yours to learn from and build with. The fonts are open-source (SIL Open Font License): Vazirmatn for the Persian UI, Lalezar for display, Readex Pro for editorial, plus Inter, JetBrains Mono, Archivo Black and Instrument Serif for the Latin roles.
